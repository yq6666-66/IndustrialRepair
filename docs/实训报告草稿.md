## 一、目的与意义

### 1.1 实训目的

本次实训旨在通过实践，学习工业维修智能化零件分配平台的设计理念，理解视觉识别技术在传统维修管理系统中的落地应用，综合运用图像分析、物料清单（BOM）与智能物料分析等技术，构建"拍照—识别—算料"一体化的智能维修解决方案。维修人员报修时只需使用客户端拍照上传，系统即可自动分析照片中涉及的维修部件与零件，并结合材料（配件）表中的配件信息，智能推算出本次维修各类材料及数量，从而提升维修效率、降低备件浪费、强化成本管控。

通过本项目掌握：C# WinForm 桌面应用开发、SunnyUI 第三方控件库与现代界面开发、ADO.NET 数据库编程（含事务）、SQL Server 存储过程/触发器/视图、软件安全（bcrypt/RBAC/防注入）、串口通信与物联网设备集成、数据可视化大屏，以及生产环境部署与性能调优，培养工程化意识与规范。

## 二、需求分析

- **角色（RBAC）**：报修人（报修与进度查询）、维修工程师（接单/完工/**材料审阅**/算料）、配件库管理员（配件与出入库）、系统管理员（账号/角色/日志）。权限在界面按钮显隐与服务层各校验一次，越权直接调用服务被拒绝。
- **核心用例**：注册/登录（验证码、找回密码、MFA）→ 报修（拍照压缩上传+识别 Top3 候选留痕）→ 派单 → 接单 → **材料审阅（工程师确认重点零件，或选择仅整机 BOM）**→ 智能算料生成领料单（审阅快照固化）→ 领料出库（事务扣库存、低库存预警）→ 完工 → 大屏统计与月度报表。
- **非功能**：口令 bcrypt 哈希存储、登录失败 5 次锁定 10 分钟、30 分钟会话超时、全链路操作日志、SQL 参数化防注入；数据库结构版本化迁移（升级失败整体回滚、可重试）。

## 三、系统设计

### 3.1 总体架构

三层架构：`IndustrialRepair.UI`（WinForm+SunnyUI 界面）→ `IndustrialRepair.BLL`（认证/工单/算料/识别/串口业务）→ `IndustrialRepair.DAL`（ADO.NET DbHelper 与仓储）＋ `IndustrialRepair.Models`（实体）。

### 3.2 数据库设计（E-R 摘要）

核心表 17 张：sys_role、sys_user、sys_permission、sys_role_permission、sys_login_log、sys_operation_log、part_category、part、device、bom、work_order、work_order_record、picking_list、picking_item、part_stock_log、stock_alert、schema_version（结构版本登记）。

关系要点：设备 1—N BOM 项—配件；工单 N—1 设备/报修人，1—N 流转记录；领料单 1—N 明细；配件 1—N 库存流水/预警。

### 3.3 关键数据库对象

- 存储过程：usp_CreateOrder（建单，applock 并发安全单号）、usp_AssignOrder/TakeOrder/CompleteOrder/CancelOrder（流转）、**usp_ReviewMaterials（材料审阅：字段与留痕同事务）**、usp_GeneratePicking（审阅闸门 + BOM×冗余算料 + 审阅快照 + 重点标记/追加行，事务+行锁）、usp_IssuePicking（出库扣库存，不足回滚）、usp_StockIn（入库闭环预警）、usp_GetDashboard（大屏统计）。
- 触发器：trg_WorkOrder_Record（仅真实新增与状态变化留痕）、trg_Part_StockAlert（库存跌破下限预警）、trg_PickingItem_Trace（明细留痕）。
- 视图：vw_WorkOrder_Full、vw_PickingDetail、vw_RepairReport、vw_LowStock。
- **写入约束**：part/bom/picking_item CHECK（非负/正数）；「一工单至多一张未出库领料单」唯一过滤索引。
- **版本化迁移**：dbo.schema_version 记录结构版本；各迁移在单一事务内按 GO 批次执行，失败整体回滚、重启可重试；存储过程/触发器/视图按脚本哈希增量刷新。

### 3.4 拍照识别方案（V2：ZXing + OpenCvSharp × 特征库融合）

三级流水线：① ZXing.Net（开源条码库）解码照片中的二维码/条码（PART:编码）→ 直接命中配件（匹配分数 100）；② OpenCvSharp（开源 OpenCV 封装）提取视觉特征：CLAHE 自适应增强 → 中心 ROI 均值色 → Canny 边缘 → 最大轮廓圆度 4πA/P² 判形状（圆/矩形/六方）、轮廓面积占比判尺寸；③ 与配件特征库（part.FeatureJson 颜色/形状/尺寸）加权最近邻融合排序，输出 Top-3 候选与可解释理由（候选按编码去重、同分稳定排序）。匹配分数为相似度加权值而非概率，低于 60 提示需人工核对。OpenCV 原生库异常时自动降级纯托管规则路径，保证演示稳定；架构上识别引擎以 IImageRecognizer 接口隔离，课程模型或 CNN 可同接口替换，并配套 RecognizeEval 评测工具量化任意实现的 Top1/Top3 与混淆矩阵。

## 四、详细实现（要点）

1. **认证与安全**：bcrypt(cost=11) 哈希；图形验证码（抗旋转+噪线）；MFA 邮箱验证码（模拟）；注册写入采用 C# 侧 BeginTransaction/Commit/Rollback 演示多语句事务；会话令牌+滑动 30 分钟超时。
2. **工单流转**：全部经存储过程状态机（Pending→Assigned→Working→Done/Cancelled），触发器自动写维修历史记录。
3. **材料审阅与智能算料（整机 BOM 语义）**：生成领料单前必须完成材料审阅——工程师在工单详情页从识别候选确认重点零件（BOM 内仅 ★ 标记不改数量；BOM 外需人工填写基础用量与理由，按 CEILING(用量×冗余) 追加），或选择"仅按整机 BOM 配料"；存在未出库领料单时禁止更改审阅；生成时把审阅结果以快照固化到领料单，历史清单始终可解释。冗余系数 1.00~2.00 可调；重复生成拦截（含并发，唯一过滤索引兜底）；usp_IssuePicking 事务扣库存并写流水，库存不足整体回滚并提示缺口。
4. **图像处理**：报修照片"一次准备"——后台线程压缩保存（最长边 800px、JPEG 75%）并识别，预览与提交共用同一文件与候选；识别失败清空候选、处理期间禁用提交，界面不阻塞。识别分数为匹配分数（颜色/形状/尺寸加权），低于 60 提示需人工核对，不冒充概率。
5. **串口**：SerialPort 帧协议 `PART:配件编码`；扫码源以 IScannerInput 接口隔离（真实串口/模拟器/图片扫码/手动录入共用同一查询流程）；无硬件时内置扫码模拟器，UI 线程安全封送。
6. **大屏**：汇总卡片 + UIBarChart（状态/排行）+ UILineChart（近 7 日）+ 预警表。
7. **二维码闭环（QRCoder + ZXing.Net，开源）**：配件库一键生成"PART:编码"二维码标签（含名称，可另存打印）；串口页「从图片扫码」与报修照片经 ZXing 解码直达配件，与扫码模拟器构成完整闭环。
8. **Excel 报表（ClosedXML，开源）**：领料清单/维修月报/配件库存一键导出 .xlsx，带标题、表头样式、冻结首行、自适应列宽与合计行。
9. **MQTT 物联网（MQTTnet 4.3，开源）**：应用内嵌 MqttServer（127.0.0.1:18835）无需外部 Broker；设备模拟器按 factory/{设备}/telemetry 主题发布温度/振动 JSON；订阅上屏（实时温度曲线 + 设备健康表）；温度>75℃ 或振动>8.0mm/s 自动创建 [IoT自动报修] 工单（同设备 10 分钟冷却防重复），全流程留痕。
10. **工程化**：全局异常兜底（UI 线程/后台线程/Task 三路捕获 → 滚动文件日志 + 友好弹窗）；LocalDB 冷启动 3 次梯度重试；关键操作按钮防双击。

### 4.1 开源组件集成（对应任务书"直接使用热门开源项目"）

直接依赖 8 个热门开源库：SunnyUI（~4k★，界面，**GPL-3.0-only**）、OpenCvSharp（~6.1k★，视觉，Apache-2.0）、QRCoder（~3.7k★，二维码生成，MIT）、ZXing.Net（~2.8k★，条码解码，Apache-2.0）、ClosedXML（~4.6k★，Excel，MIT）、MQTTnet（~4k★，MQTT，MIT）、BCrypt.Net-Next（口令哈希，MIT）、xunit（测试，Apache-2.0）。许可证以官方 NuGet 包元数据为准（SunnyUI 为 GPL-3.0-only，具有传染性，课设/学习场景可用，商业化发布需注意）。另借鉴 SunnyUI 官方 Demo（多页面框架/图表用法）、opencvsharp_samples（轮廓/CLAHE 范式）、CMMS 领域开源项目（工单状态机/资产台账设计）。详见《GitHub开源参考.md》。

## 六、部署与运行

- 开发环境：Windows 11、.NET SDK 8、Visual Studio 2022、SQL Server LocalDB、SunnyUI 3.9.8（NuGet）。
- 一键部署：`dotnet publish -c Release` 后拷贝输出目录，目标机安装 .NET Desktop Runtime 8 与 LocalDB，程序内点「一键初始化」自动建库播种。

## 七、总结

本项目完整落地了任务书"拍照—识别—算料"的业务闭环与全部技术要求（WinForm/SunnyUI/ADO.NET 事务/存储过程触发器视图/安全/串口/大屏/MQTT），并按工程规范补齐了版本化数据库迁移、材料审阅闭环（识别候选→人工确认→整机 BOM 配料留痕）、服务层权限二次校验、独立测试库隔离与识别评测工具；单元测试 32/32、端到端冒烟 58/58、SQL 冒烟与数据库升级演练全部通过。收获：三层架构划分、事务边界设计、以存储过程承载业务状态机、并发写入的锁与约束设计、特征库识别的可解释性权衡、以及"评测出真数"的验证意识。不足与展望：识别为特征库匹配（分数非概率，合成图 Top1 0/3 已如实记录），待课程模型到位后经 IImageRecognizer 接口替换并以独立真实图集评测；真实扫码枪与山海鲸大屏需实物验证；工单可扩展移动端（MAUI）与消息推送。
