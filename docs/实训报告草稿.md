## 一、目的与意义

### 1.1 实训目的

本次实训旨在通过实践，学习工业维修智能化零件分配平台的设计理念，理解视觉识别技术在传统维修管理系统中的落地应用，综合运用图像分析、物料清单（BOM）与智能物料分析等技术，构建"拍照—识别—算料"一体化的智能维修解决方案。维修人员报修时只需使用客户端拍照上传，系统即可自动分析照片中涉及的维修部件与零件，并结合材料（配件）表中的配件信息，智能推算出本次维修各类材料及数量，从而提升维修效率、降低备件浪费、强化成本管控。

通过本项目掌握：C# WinForm 桌面应用开发、SunnyUI 第三方控件库与现代界面开发、ADO.NET 数据库编程（含事务）、SQL Server 存储过程/触发器/视图、软件安全（bcrypt/RBAC/防注入）、串口通信与物联网设备集成、数据可视化大屏，以及生产环境部署与性能调优，培养工程化意识与规范。

## 二、需求分析

- **角色（RBAC）**：报修人（报修与进度查询）、维修工程师（接单/完工/算料）、配件库管理员（配件与出入库）、系统管理员（账号/角色/日志）。
- **核心用例**：注册/登录（验证码、找回密码、MFA）→ 报修（拍照压缩上传+识别）→ 派单 → 接单 → 智能算料生成领料单 → 领料出库（事务扣库存、低库存预警）→ 完工 → 大屏统计与月度报表。
- **非功能**：口令 bcrypt 哈希存储、登录失败 5 次锁定 10 分钟、30 分钟会话超时、全链路操作日志、SQL 参数化防注入。

## 三、系统设计

### 3.1 总体架构

三层架构：`IndustrialRepair.UI`（WinForm+SunnyUI 界面）→ `IndustrialRepair.BLL`（认证/工单/算料/识别/串口业务）→ `IndustrialRepair.DAL`（ADO.NET DbHelper 与仓储）＋ `IndustrialRepair.Models`（实体）。

### 3.2 数据库设计（E-R 摘要）

核心表 15 张：sys_role、sys_user、sys_permission、sys_role_permission、sys_login_log、sys_operation_log、part_category、part、device、bom、work_order、work_order_record、picking_list、picking_item、part_stock_log、stock_alert。

关系要点：设备 1—N BOM 项—配件；工单 N—1 设备/报修人，1—N 流转记录；领料单 1—N 明细；配件 1—N 库存流水/预警。

### 3.3 关键数据库对象

- 存储过程：usp_CreateOrder（建单）、usp_AssignOrder/TakeOrder/CompleteOrder/CancelOrder（流转）、usp_GeneratePicking（BOM×冗余算料，事务+回滚）、usp_IssuePicking（出库扣库存，不足回滚）、usp_StockIn（入库闭环预警）、usp_GetDashboard（大屏统计）。
- 触发器：trg_WorkOrder_Record（流转自动留痕）、trg_Part_StockAlert（库存跌破下限预警）、trg_PickingItem_Trace（明细留痕）。
- 视图：vw_WorkOrder_Full、vw_PickingDetail、vw_RepairReport、vw_LowStock。

### 3.4 拍照识别方案（V2：ZXing + OpenCvSharp × 特征库融合）

三级流水线：① ZXing.Net（开源条码库）解码照片中的二维码/条码（PART:编码）→ 直接命中配件，置信 100%；② OpenCvSharp（开源 OpenCV 封装）提取视觉特征：CLAHE 自适应增强 → 中心 ROI 均值色 → Canny 边缘 → 最大轮廓圆度 4πA/P² 判形状（圆/矩形/六方）、轮廓面积占比判尺寸；③ 与配件特征库（part.FeatureJson 颜色/形状/尺寸）加权最近邻融合排序，输出 Top-3 候选与可解释理由。OpenCV 原生库异常时自动降级纯托管规则路径，保证演示稳定；架构上识别引擎独立成类，可平滑替换为 CNN 或在线 AI 接口。

## 四、详细实现（要点）

1. **认证与安全**：bcrypt(cost=11) 哈希；图形验证码（抗旋转+噪线）；MFA 邮箱验证码（模拟）；注册写入采用 C# 侧 BeginTransaction/Commit/Rollback 演示多语句事务；会话令牌+滑动 30 分钟超时。
2. **工单流转**：全部经存储过程状态机（Pending→Assigned→Working→Done/Cancelled），触发器自动写维修历史记录。
3. **智能算料**：usp_GeneratePicking 读取设备 BOM，用量×冗余系数（默认 1.10，任务书"留有一定冗余"）向上取整生成明细；重复生成拦截；usp_IssuePicking 事务扣库存并写流水，库存不足整体回滚并提示缺口。
4. **图像处理**：报修照片本地压缩（最长边 800px、JPEG 75%）后保存，符合"本地拍照压缩上传"要求。
5. **串口**：SerialPort 帧协议 `PART:配件编码`；无硬件时内置扫码模拟器每 4 秒推帧，UI 线程安全封送。
6. **大屏**：汇总卡片 + UIBarChart（状态/排行）+ UILineChart（近 7 日）+ 预警表。
7. **二维码闭环（QRCoder + ZXing.Net，开源）**：配件库一键生成"PART:编码"二维码标签（含名称，可另存打印）；串口页「从图片扫码」与报修照片经 ZXing 解码直达配件，与扫码模拟器构成完整闭环。
8. **Excel 报表（ClosedXML，开源）**：领料清单/维修月报/配件库存一键导出 .xlsx，带标题、表头样式、冻结首行、自适应列宽与合计行。
9. **MQTT 物联网（MQTTnet 4.3，开源）**：应用内嵌 MqttServer（127.0.0.1:18835）无需外部 Broker；设备模拟器按 factory/{设备}/telemetry 主题发布温度/振动 JSON；订阅上屏（实时温度曲线 + 设备健康表）；温度>75℃ 或振动>8.0mm/s 自动创建 [IoT自动报修] 工单（同设备 10 分钟冷却防重复），全流程留痕。
10. **工程化**：全局异常兜底（UI 线程/后台线程/Task 三路捕获 → 滚动文件日志 + 友好弹窗）；LocalDB 冷启动 3 次梯度重试；关键操作按钮防双击。

### 4.1 开源组件集成（对应任务书"直接使用热门开源项目"）

直接依赖 7 个热门开源库：SunnyUI（~4k★，界面）、OpenCvSharp（~6.1k★，视觉）、QRCoder（~3.7k★，二维码生成）、ZXing.Net（~2.8k★，条码解码）、ClosedXML（~4.6k★，Excel）、MQTTnet（~4k★，MQTT）、BCrypt.Net-Next（口令哈希）；均为 MIT/Apache-2.0 宽松协议。另借鉴 SunnyUI 官方 Demo（多页面框架/图表用法）、opencvsharp_samples（轮廓/CLAHE 范式）、CMMS 领域开源项目（工单状态机/资产台账设计）。详见《GitHub开源参考.md》。

## 六、部署与运行

- 开发环境：Windows 11、.NET SDK 8、Visual Studio 2022、SQL Server LocalDB、SunnyUI 3.9.8（NuGet）。
- 一键部署：`dotnet publish -c Release` 后拷贝输出目录，目标机安装 .NET Desktop Runtime 8 与 LocalDB，程序内点「一键初始化」自动建库播种。

## 七、总结

本项目完整落地了任务书"拍照—识别—算料"的业务闭环与全部技术要求（WinForm/SunnyUI/ADO.NET 事务/存储过程触发器视图/安全/串口/大屏），24 项自动化断言与 SQL 冒烟全部通过。收获：三层架构划分、事务边界设计、以存储过程承载业务状态机、特征库识别的可解释性权衡。不足与展望：识别准确率依赖特征库覆盖度，后续可引入 CNN 或多模态大模型接口；工单可扩展移动端（MAUI）与消息推送。
